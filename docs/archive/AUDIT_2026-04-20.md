### PILLAR 2 — Vector Index (36 checks)
- Flat L2 → **RaBitQ 1-bit** (~32× smaller, recall 0.95)
- Add **usearch HNSW** fallback via feature flag for >1M vecs
- Disk-spill plan: LanceDB shard when count > 10M
- ANN recall eval harness (random 1k queries, GT from flat)
- Per-shard index (bandit already routes)
- Prefilter via FTS5 candidate set → vec rerank (cut work 10×)

**Target**: 6ms → **0.8ms** p95 at 1M vecs via RaBitQ+HNSW.

### PILLAR 3 — FTS / BM25 (36)
- FTS5 porter ok for EN; swap `unicode61` params for DE (remove_diacritics=1 keep umlaut mapping)
- Add `trigram` tokenizer variant for code/IDs
- BM25 weights (k1=1.2, b=0.75) → **tune per corpus** via LightGBM gridsearch
- Phrase boost, proximity rank
- Snippet extraction in-SQL (avoid post-process)
- `contentless-delete` FTS5 mode for memory cut

### PILLAR 4 — Hybrid Fusion (36)
**Current**: RRF k=60 (static).
**Upgrade**: LightGBM LambdaMART reranker.
- Features: bm25, cos, rrf_rank, doc_age, click_freq, heat, title_match, path_depth, query_len
- Train on accept/miss log (already captured in synapse-learn)
- Export ONNX → load in Rust via ort
- Expected: NDCG@10 +6-9 over RRF
- Fallback: RRF when LTR-confidence < 0.5

**→ superml skill direct hit — Pillar 4 ist Core-Anwendung.**

### PILLAR 5 — Reranking (36)
- **Cross-encoder**: Jina-reranker-v2-base-multilingual (278MB, 40ms/32) → top-10 from top-100
- **Cheap layer**: LambdaMART (0.2ms) → top-50 from top-500
- **SOTA optional**: ColBERT-v2 via PyLate service (sidecar, not Rust-native)
- Cascade: FTS+vec 500 → LambdaMART 50 → Jina 10
- Latency budget: 60ms total @ p95
- Reranker cache keyed by (query_hash, doc_id)

### PILLAR 6 — Chunking (36)
- Current: none (full-doc)
- Add **Late-chunking** (Jina): embed 8k ctx, pool per 256-tok chunk
- **Contextual Retrieval** (Anthropic): LLM prepends chunk-context — gate behind `--contextual` flag, use Haiku 4.5 for cost (€0.018/100)
- Propositional chunking for QA corpora
- Parent-doc retrieval: small-chunk match → return parent
- Chunking strategy per-source (code vs prose vs json) via regex routing

**Expected**: retrieval failure −49% (Anthropic paper), −67% with reranker.

### PILLAR 7 — Self-Learning (36)
Bottleneck areas:
- **Signals**: binary accept/miss → add dwell-time, scroll-depth, click-through, explicit 👍/👎
- **Drift**: PCA stub → replace with **smartcore PCA** or **linfa-reduction**
- **Calibration**: Platt/isotonic on rerank scores
- **Bandit**: Thompson per-shard ok → upgrade to **LinUCB** with query embedding as context
- **LTR retrain**: nightly LambdaMART on feedback log
- **Synthetic data**: InPars-v2 via Haiku → augment cold-start corpora
- **Online update**: vowpal-wabbit contextual bandit for query→shard routing
- **Eval gate**: block promotion if NDCG@10 regresses

**→ superml Pillar 7 drives this — LambdaMART + EBM audit + LinUCB.**

### PILLAR 8 — DB / Storage (36)

## 1000-Test Benchmark Plan

### Test Corpora (5)
| Corpus | Size | Purpose |
|--------|------|---------|
| BEIR nfcorpus | 3.6k | medical retrieval baseline |
| MTEB Touche-2020 | 380k | argument retrieval |
| MS-MARCO subset | 100k | passage reranking |
| Synapse-self (your ~/.claude logs) | 50k | personal relevance |
| Code corpus (rust-std + 10 repos) | 30k | code retrieval |

### Test Axes (200 configs)
- Embedders (5): BGE-small, Arctic-v2-m, Jina-v3, mxbai-large, Qwen3-0.6B
- Vec indices (4): flat, sqlite-vec HNSW, usearch HNSW, RaBitQ+HNSW
- Fusion (5): lex-only, vec-only, RRF, LTR-LGBM, LTR+rerank
- Chunking (4): none, fixed-512, late-chunk, contextual
- Rerankers (5): none, LGBM, Jina-v2, mxbai, ColBERT-v2
- Dim-reduction (5): 384, 256, 128, 64 Matryoshka, RaBitQ-1bit
- Result: 5×4×5×4×5×5 = 10,000 combos → sample 200 via **optuna TPE**

### Test Queries × Corpora × Configs
- 5 corpora × 200 configs × 100 queries = **100,000 data points** → downsample via stratified to **1000 premium tests** per run

### Metrics Collected (per test)
- NDCG@10, NDCG@100, MRR, recall@100, p50/p95/p99 latency, RSS memory, disk, index-build-time, QPS at concurrency=16

### Runtime
- 1000 tests × avg 2s/test = ~35 min per bench pass
- Nightly launchd via existing stop-hook pattern
