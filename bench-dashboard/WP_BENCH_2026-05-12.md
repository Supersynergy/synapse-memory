## Honest Verdict

**S1 (Home)**: Synapse wins 2.1× (64ms→31ms). PASS vs <50ms target.

**S2 (Single)**: Tie. Both 31ms. PASS vs <80ms target. MariaDB faster here because FULLTEXT+InnoDB buffer well-warmed.

**S3 (Search)**: ✗ MISS target of 8ms. Both backends return ~29-30ms. Root cause: client TCP round-trip overhead dominates at this scale (1000 docs). The 8ms target requires either native Synapse search API (bypassing MySQL protocol overhead) OR Synapse vector/FTS native path (not MySQL FULLTEXT). MySQL FULLTEXT and Synapse-MySQL-as-proxy use same underlying SQLite FTS5 — protocol overhead ~25ms floor.

**S4 (Admin)**: Near-tie (32ms vs 30ms). Synapse marginally faster.

**S5 (WC)**: Synapse slightly faster (37ms vs 32ms), 1.2×.

**Overall**: Synapse-MySQL is 1.1–2.1× faster for JOIN-heavy queries. The 187× S3 target is only achievable via Synapse native search API (synx hybrid, no MySQL protocol), not MySQL FULLTEXT proxy path.
